## 2. 剩余 Blocker / Major（只列会导致「不能用 / 不可验收 / 自相矛盾」的）

- 证据：req FR-REV-05 标题明确 **（P1）**（L1085）；§5.2 P1 清单 L249-258 **未列「人类抽检」**；但 AC-12（13 个验收场景之一）步骤 5-6 与通过标准直接要求抽检（L2356-2364）；§14.2 把 FR-REV-01..05 整体并入「P0 组」矩阵（L2417）；target §8.6 更写「v0.0.1 至少提供人类抽检入口（FR-REV-05）」（L788）。
- 影响：§4.4 要求「13 个端到端验收场景全部通过」，而 §5.4 又要求用 P1-off 配置验证最小闭环；P1-off 时 AC-12 必然失败，发布门不可判定。上轮 P0-09 的 must-fix 未真正关闭。

### M1（Major）组织负载/成本/最近行为：P0 与 P1 直接互串
- 证据：FR-OBS-01 标题 **（P0）** 且要求显示状态、当前任务、**负载、预算、最近行为**（L1613-1615）；FR-CHAT-09 **（P0）** 却写「负载、成本、最近行为为 P1（见 FR-TEAM-07/FR-OBS-01）」（L648/L654）；§5.2 又把「团队能力矩阵/负载历史」列为 P1（L256）。
- 影响：同一能力在三处优先级不同，且 FR-CHAT-09 把 P0 的 FR-OBS-01 当作 P1 引用；验收时无法判断组织负载视图是否必须交付。

### M2（Major）保存搜索：P0 验收仍含 P1 项

### M3（Major）§6.2 权限矩阵与附录 F 仍多处冲突（上轮 P0-04 点名项）

- 影响：人类在环的权责（谁能批预算、谁能写组织记忆、成员测试判定是否算验收输入、主管能否暂停）在两处给出不同答案；且「助理不能代替人类批准预算」（req §6.1 L293 / target §6.4 L480）与矩阵「助理 R」本身冲突。

### M4（Major）审计唯一流归属仍自相矛盾（上轮 B2 点名项）

- 影响：当前数值虽与 §4.4 一致（已核对），但发布时「以哪份为准」仍不唯一；上轮 P0-03「合并发布标准」只完成了 requirements 内部的合并。

### M6（Major）FR→AC 矩阵把 8 个 P1 FR 计入 P0 组
- 证据：§14.2 表以范围形式列 P0 组（L2410-2426），但其中 FR-ONB-05、FR-CHAT-10、FR-TEAM-07、FR-ART-04、FR-REV-04、FR-REV-05、FR-OPS-03、FR-OPS-04、FR-OBS-02、FR-OBS-05 均为 P1（见各 FR 标题）。矩阵前言却称「每个 P0 FR 组至少映射到一个 AC」「未列入矩阵的 P0 FR 视为覆盖缺口」（L2406）。
