# Lignting Agents 故障排查（0.0.1 草稿）

> 状态：草稿（Q1）。命令与路径按 Windows 主环境编写；macOS/Linux 把路径分隔符与启动命令换成对应形式。
> 通用步骤：先看终端最后 50 行 → 数据目录 logs/ → 设置页导出诊断包（脱敏）。不要直接编辑 lignting.db。

## 启动

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 端口占用（listen tcp 127.0.0.1:8787: bind） | 已有实例/其他程序占用 | 换端口 -Port 8788；或结束旧进程后重启 |
| 数据目录不可写/权限拒绝 | 目录在受保护位置、被杀软锁 | 换到用户目录或 D 盘本地目录；确认当前用户可写 |
| 数据目录在 OneDrive/NAS/网络盘 | SQLite WAL 不支持网络文件系统 | 移到本机盘；不要放同步盘 |
| database is locked | 另一个进程持有写连接/备份未完成 | 关闭其他实例；等待备份结束；不要直接复制 db 文件 |
| 启动即退出，无日志 | 配置损坏/迁移失败 | 备份数据目录后查看 logs；必要时用导出数据恢复 |

## 模型

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 401/403 | Key 无效/过期/额度不足 | 设置页重新填 Key；确认 DeepSeek 控制台可用 |
| 429 | 限流 | 等待自动重试；降低并发；检查预算与重试上限 |
| 503/超时 | 供应商故障/网络 | 平台应可浏览/搜索/导出；Agent turn 标记失败可重试；不要反复全量重发 |
| 无 Key | 首次向导未填 | 平台可启动；Agent 回复显示「未配置模型」；补 Key 后重试 |
| 回复中断/半条消息 | 流式连接中断/进程崩溃 | 刷新后应显示「已中断」；重试创建新回复，不覆盖历史 |

## 检索

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 中文 2 字搜不到 | 索引未建/分词异常/刚启动 | 设置页重建索引；确认写入后 ≤100ms 可搜；检查索引版本 |
| 刚发的消息搜不到 | 索引事务失败/索引过期 | 看诊断包索引状态；重建索引；若复现提缺陷（P0） |
| 删除的消息还能搜到 | 索引未同步（隐私事故） | 立即重建索引并记录审计；提 P0 缺陷 |
| 结果很少/分页怪 | 权限过滤/分页游标 | 确认当前部门/权限；换过滤条件；报告 exact 查询与期望结果 |

## 任务与审批

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 任务卡在 in_review | 评审人不可用/SLA 超时 | 主管改派（留记录）；blocker 24h 内响应，超时升级 |
| G3 提交被拒 | 验收标准缺证据/核对表未填 | 打开核对表看缺失项；补证据/结论后重试 |
| 审批一直 pending | 人类未处理/TTL 未触发 | 收件箱查看；TTL 到期会标记阻塞并提醒，不自动执行 |
| 批量审批被拒 | 含双钥匙/不可逆动作 | 逐条审批；双钥匙动作必须作者之外的第二人确认 |
| Agent 一直 running | 模型/工具卡住/预算阻塞 | 查看 Agent 状态与最近行为；暂停/停止；检查预算与工具超时 |

## 写入与时间线

| 现象 | 可能原因 | 处理 |
|---|---|---|
| write_file 被拒 base_hash | 其他 Agent 已写同一文件 | 重新读取/变基后重试；不要强制覆盖 |
| 两个 Agent 写不同文件也串行 | 默认全局串行 | 正常设计；需要并行时改配置（v0.0.1 验收只保证全局串行） |
| 时间线少/超过 30 条 | 保留上限配置 | 检查 write_timeline_limit（默认 30）；旧记录按 created_at 淘汰 |
| bash 改了文件但时间线没有 | 绕过 WriteTool | 应被标记「不受管变更」/触发审批；若没有，提缺陷 |

## 记忆

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 改了记忆但 Agent 还用旧值 | 当前会话已注入旧上下文 | 新会话验证；检查「本次回答使用了哪些记忆」；确认旧版本/墓碑 |
| 删除后仍被引用 | 缓存/快照/注入日志 | 检查删除传播（索引/缓存/快照）；若复现提 P0 |
| 记忆越权可见 | 视图/权限配置错误 | 检查 visibility 与部门隔离；审计读取留痕；提 P0 |
| 候选一直不晋升 | 审核队列积压/自动合并关闭 | 打开待审队列批准/拒绝/合并；看记忆失败队列与冷却 |

## 备份与恢复

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 备份文件明显偏小 | 只备份了 db，漏了 artifacts/workspace | 用系统备份功能而非手工复制；确认清单 |
| 恢复后搜索为空 | 索引未重建 | 设置页重建索引并抽样校验 |
| 恢复失败 | 版本不兼容/文件损坏 | 恢复前校验版本与完整性；失败回滚到原数据目录；保留备份副本 |
| 导入冲突 | 目标工作区已有数据 | 导入前确认策略（跳过/合并/覆盖需显式确认） |

## 安全

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 浏览器提示 Web 风险 | 本地 HTTP/证书 | 默认只绑 loopback；远程访问用 SSH 端口转发或覆盖网络，不自建公网 TLS |
| 跨站请求被拒 | Origin/Host/CSRF 校验 | 正常安全行为；不要关闭校验，改从前端入口操作 |
| Key 出现在日志里 | 脱敏漏配/第三方日志 | 立即轮换 Key；导出诊断包前确认脱敏；提 P0 |
| Agent 尝试越权 | 工具白名单/审批缺失 | 暂停 Agent；检查工具权限与审批记录；导出审计；提缺陷 |

## 诊断包

设置 → 诊断 → 导出诊断包（脱敏）。应包含：版本、配置摘要（Key 脱敏）、最近错误、数据库/索引状态、Agent 状态、日志时间线。**不要**手工把 secrets.json 或完整数据库发给他人。

## 仍然无法解决

1. 记录：时间、操作、预期、实际、错误码、trace/turn id。
2. 在任务线程/消息里附上诊断包与日志时间点。
3. 若涉及数据丢失、越权、密钥泄漏、删除后仍可搜：按 P0 处理，立即暂停并保留现场。
