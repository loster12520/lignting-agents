# Lignting Agents 15 分钟演示脚本（0.0.1 草稿）

> 状态：草稿（Q1）。演示目标是让观众在 15 分钟内看到「目标 → 组部门 → 任务 → 讨论 → 评审 → G3 → 记忆/检索」的闭环，而不是看完所有功能。
> 建议用 mock 模型预演流程，再用真实 Key 跑一次完整版；每步记录证据（截图/审计 ID/耗时/成本）。

## 0. 开场（1 分钟）

一句话：**「一个人，一个助理，三个部门，把一个真实需求从想法做到验收；全部在本机。」**

## 1. 启动与首次见面（2 分钟）

1. .\scripts\dev.ps1（或 -Mock 演示模式）；打开 <http://127.0.0.1:8787>。
2. 向导四项：数据目录、Key、预算、称呼。
3. 助理自我介绍：能做什么、不做什么、如何暂停。
4. 说明：默认只本机可访问；数据在本地；没有 Key 也能浏览/搜索/导出。

**证据**：T1 计时 ≤10 分钟；终端地址；审计里的 setup 记录。

## 2. 说清楚目标（2 分钟）

1. 输入：「我想把现在的 CLI 工具做成一个带 Web 界面的产品，先做最小可用版。」
2. 助理澄清 → 生成项目意图卡；观众看到「未确认前不会建部门」。
3. 问一个单次问题：「这个功能大概需要几天？」助理直接回答，不建任务。

**证据**：意图卡版本；单次问答来源；部门数=0。

## 3. 组部门与 G1（3 分钟）

1. 助理给「精简版/完整版」蓝图：产品/研发/测试部门、角色卡、分工视角、预算、前三风险。
2. 现场改一个参数（如人数/预算），批准 G1。
3. 系统 provisioning：部门、主管/员工、部门群聊、任务板、记忆空间。
4. 主管 kickoff：复述目标/风险/第一里程碑，不再单独要求审批。

**证据**：T2 累计 ≤30 分钟；幂等重试不重复；暂停/恢复一次。

## 4. 第一个任务与部门内讨论（3 分钟）

1. 产品写 PRD 与验收标准；主管拆任务，写明每个员工的**分工视角**。
2. 研发 A/B 对接口字段有分歧 → 部门群聊讨论：视角+证据，每人≤5、总≤15；主管裁决。
3. 展示任务状态机：discussing → in_progress。

**证据**：讨论条数；裁决记录；任务时间线。

## 5. 实现、评审与返工（2 分钟）

1. 研发提交产出物 v1；测试提交 blocker 挑战单（带证据/复现命令）。
2. 研发返工 v2；旧裁决仍可查；作者≠评审者。
3. 展示共享写工具：写事件、base_hash、diff、时间线（30 条上限）。

**证据**：挑战单证据；v1/v2 对比；file_timeline。

## 6. G3 与人类核对（1.5 分钟）

1. 部门主管填验收核对表：AC1 有证据通过、AC2 缺证据、AC3 需人类判断。
2. 尝试 G3 → 被阻止；补证据后 G3 卡片显示核对表/成本/风险/产出物版本。
3. 批准 G3；任务 done；产出归档；记忆候选提交。

**证据**：G3 缺失项提示；核对表版本；审计无未记录审批。

## 7. 记忆与检索复盘（1.5 分钟）

1. 新会话问「上次为什么没上 GraphQL？」→ 助理给决策/辩论/任务来源。
2. 打开「本次回答使用了哪些记忆」；修改一条人类偏好；新会话生效。
3. 搜索「登录 限流」：中文 2 字命中、按部门/时间过滤、跳转原消息；删除的消息搜不到。

**证据**：来源链接；注入快照；Recall@10/延迟记录。

## 8. 安全与注意力（1 分钟）

1. 收件箱四类通知：只有「需要决定/阻塞」实时打扰。
2. 批量审批低风险；双钥匙动作被拒绝批量。
3. 暂停一个 Agent / 全局紧急停止；恢复后状态保留。

**证据**：收件箱条目；TTL 提醒；审计链。

## 9. 收尾（1 分钟）

- 数据在本机；可导出、可备份、可删除；
- 15 个 AC 对应 15 个可执行测试与证据命令（见 ac-matrix.md）；
- 下一步：Beta 3 名用户完成 T2、2 名完成 T3。

## 演示前检查清单

- [ ] 干净数据目录（不要用真实工作区）。
- [ ] Key 有效/或 mock 模式；预算足够。
- [ ] 网络可用（真实模式）；已准备一个真实小需求。
- [ ] 录屏/截图工具；审计页与搜索页已打开。
- [ ] 预演一次，确认每步耗时；准备失败分支（模型超时/预算暂停）的话术。
