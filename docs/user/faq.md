# Lignting Agents FAQ（0.0.1 草稿）

> 状态：草稿（Q1）。回答按 v0.0.1 目标行为；「当前是否可用」以实施进度为准。

## 基本

**Q1. 它和 ChatGPT / Claude / 编码 Agent 有什么区别？**
聊天机器人给答案；编码 Agent 在仓库里改代码。Lignting 把**组织**运行起来：部门、任务、产出物版本、评审、决策记录、长期记忆与人类闸门。对话是工作界面，不是产品目的。

**Q2. 我需要会写代码吗？**
不需要写代码，但需要能说清目标、验收标准与取舍，并愿意在 G1/G2/G3 做决定。目标用户是技术型独立开发者/小项目 Tech Lead。

**Q3. 为什么一定要 DeepSeek API Key？能离线吗？**
v0.0.1 只接 DeepSeek。没有 Key 时平台能启动、浏览、搜索、导出，但 Agent 不能生成回复（会显示可读错误并允许重试）。数据与界面是本地的，模型调用是唯一默认外联。

**Q4. 数据存在哪里？会上传吗？**
默认在本地数据目录（SQLite + 文件）。无遥测、不上传使用数据；只有推理所需内容发给 DeepSeek。可导出为开放格式。

**Q5. 支持多人/多项目/手机吗？**
v0.0.1 单用户、单项目、浏览器即客户端；多用户 v0.3+，多项目后续版本，移动端不做原生。

## 使用

**Q6. 为什么助理要我先确认「意图卡」和「部门蓝图」？**
避免 AI 在没理解目标时组队烧钱。意图卡确认目标/范围/约束/预算；蓝图确认部门/角色/分工视角/成本。G1 一次批准蓝图+章程，之后主管 kickoff 不再重复审批。

**Q7. 为什么部门内讨论有 5/15 上限？**
团队场景里消息量与信息量严重脱钩。每人≤5 条、总≤15 条，是为了逼出「视角 + 证据 + 请求裁决点」，避免无限闲聊。超限应升级到主管裁决，而不是继续刷屏。

**Q8. 人类闸门会不会太烦？**
只有 G1/G2(高风险)/G3 与不可逆动作会打扰你；日常任务由部门主管决定并留记录。通知分四级，只有「需要决定/阻塞」实时推送，其余进收件箱，可批量/稍后/授权。

**Q9. Agent 写文件会互相覆盖吗？**
所有 Agent 共用 WriteTool：默认全局串行，写入带 base_hash，冲突拒绝/排队，生成 diff 与时间线；每文件默认保留最近 30 次修改。用 bash 绕过会被审批或标记「不受管变更」。

**Q10. 记忆会不会记错、记脏？**
写入有四道门槛（可复用/可验证/决策相关/归属明确），员工只能提交候选，主管/助理审核晋升；决策/争议强制保留双时间与证据；人类可查看、编辑、删除（留墓碑），删除后不再注入。投毒内容不能升级为系统指令。

**Q11. 辩论会不会没完没了 / 演成互相吹捧？**
辩论有硬边界：每人≤5、总≤15、R1/R2、时间盒、死锁检测（stance 不变且无新证据即升级）；异议必须保留；作者≠裁决人；人类可抽检裁决并标记有效/无效/证据不足。

**Q12. 我能中途暂停/停止吗？**
可以。支持单 Agent、单部门、全局紧急停止；暂停后保留状态，恢复不重复副作用。预算 80% 告警、100% 暂停接新任务。

## 数据与恢复

**Q13. 备份怎么恢复？**
用设置页备份（在线备份/导出，不直接复制运行中的 SQLite 文件）。恢复前校验版本/完整性，恢复后重建索引；至少每版本做一次恢复演练。备份/恢复/导出都留审计。

**Q14. 删除的数据还能搜到吗？**
软删除会同步清理检索索引，搜索与详情都不可见（审计权限除外）；记忆删除留墓碑，避免快照/缓存复活。

**Q15. 出错了怎么排查？**
看 [故障排查](troubleshooting.md)：日志在数据目录 logs/，设置页可导出脱敏诊断包；常见问题包括端口占用、Key 无效、数据目录不可写、索引过期。

## 边界

**Q16. 它会自动发布/自动付款吗？**
不会。v0.0.1 不做自动合并/发布/付款；不可逆动作必须人类审批，Agent 不能自批、不能改自己的权限。

**Q17. 为什么不做多模型/DSH/ACP？**
先证明单模型、单机、单二进制的闭环可用；多供应商与外部运行时是后续版本的能力，不作为 v0.0.1 依赖。
