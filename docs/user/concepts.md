# Lignting Agents 概念手册（0.0.1 草稿）

> 状态：草稿（Q1）。按 requirements.md 与 target.md 的目标行为编写，实现后校对。
> 一句话：**你不是在用一个聊天框，而是在运行一支有角色、任务、产出、评审与记忆的虚拟团队。**

## 1. 三层角色

~~~text
项目主管（你）
   │ 目标、预算、最终裁决、不可逆审批
   ▼
助理 Agent
   │ 澄清、划分部门、协调、注意力过滤、记忆策展
   ▼
部门主管 Agent × N
   │ 拆解、分派、解阻、质量门、对外代表
   ▼
员工 Agent（产品 / 研发 / 测试 / …）
~~~

- **项目主管（Owner）**：登录者，唯一人类。拥有 G1/G2/G3、预算、暂停与最终否决权。
- **助理 Agent**：首席幕僚。把模糊想法变成意图卡与部门蓝图；主持跨部门评审；过滤打扰；审核候选记忆。不投票、不替人类裁决、不自批。
- **部门主管 Agent**：本部门运营核心。拆任务、写验收标准、分派、解阻、组织评审、逐条核对产出、代表部门对外。不能改人类目标/预算，不能批准自己的产出，不能绕过测试红线。
- **员工 Agent**：有固定**分工视角**的专家。产品看 what/why，研发看 how/接口/数据，测试看证据与边界。作者不能评审自己的产出。

**为什么没有「统管所有部门的主管」**：v0.0.1 是固定 SOP + 有限动态；跨部门冲突由双方部门主管先谈，谈不拢交助理主持，再反馈用户。这样既保留真实争论，又不制造一个全知全能的超级 Agent。

## 2. 工作对象

| 对象 | 是什么 | 最小要求 |
|---|---|---|
| **部门** | 组织单元：主管 + 员工 + 群聊 + 任务板 + 记忆空间 | 章程、角色卡、分工视角、预算 |
| **群聊** | 项目群 / 部门群 / 临时讨论组 | 成员、可见性、发言队列、全量落库 |
| **任务** | 有目标、验收标准、owner/reviewer/approver、状态、证据的工作单元 | DoR、DoD、时间线、依赖 |
| **产出物** | 不可变版本的交付物：PRD、方案、代码、测试报告、评审、决策 | 内容 hash、版本只增不改、关联任务/评审/决策 |
| **评审** | 对某个产出物版本的挑战与裁决 | 挑战单、证据、作者≠评审者 |
| **决策记录** | 不可变的决策：背景、选项、决定、理由、异议、复查条件 | 异议保留、supersede 链、可检索 |
| **记忆** | 四层：短期上下文、触发式候选、档案、管理手册 | 来源、置信度、生效/失效、可编辑/删除 |
| **写事件 / 时间线** | 每次文件写入的 base_hash、diff、原因、任务、分支、commit | 全局串行、冲突拒绝、每文件最近 30 条 |

## 3. 任务状态机

~~~text
proposed → ready → discussing → in_progress → in_review → approved → done
              ↘ canceled      ↘ blocked ↗      ↘ changes_requested ↗
                                   ↘ failed
~~~

- **discussing**：部门内按视角讨论；每人≤5 条、总≤15 条；主管裁决后进入 in_progress 或 changes_requested。
- **blocked**：缺依赖/信息/决策；记录 owner、原因、下一步。
- **escalated / at_risk / waived 是正交标记，不是状态**；升级必须保留 from_state。
- **G3 未批准不能 done**；G3 缺任一条验收标准的证据/核对结论时不可提交。

## 4. 三个人类闸门

| 闸门 | 时机 | 你确认什么 | 可否委托 |
|---|---|---|---|
| **G1 蓝图** | 组部门前 | 目标、部门、角色、分工视角、预算、节奏、风险 | 否；一次批准蓝图+章程 |
| **G2 高风险方案** | 高风险需求开工前 | 方案、接口、依赖、风险、范围变更 | 低风险由部门主管决定并留记录 |
| **G3 最终验收** | 交付前 | 验收核对表、证据、遗留风险、是否发布 | 否；小任务可授权主管验收但必须留核对表 |

外加**不可逆动作审批**：删除、force push、对外发布、付款、权限变更。默认「一次」；「会话/始终」需范围与到期；双钥匙动作不能批量批准。

## 5. 注意力与收件箱

- 通知分级：**FYI / 需要知道 / 需要决定 / 阻塞**。
- 只有后两级实时打扰；其余进**收件箱**（持久对象）。
- 收件箱支持批量、稍后处理、授权给助理/主管（范围+到期，到期自动回收）。
- 审批有 TTL；到期不自动执行，标记阻塞并提醒。
- 人类长时间未响应时，部门可降级为只读/暂停接新任务并生成日报（可配置）。

## 6. 记忆四层

| 层 | 存什么 | 谁写 | 用户能看到什么 |
|---|---|---|---|
| 短期上下文 | 当前会话/任务窗口，可压缩 | 运行时 | 「本次回答用了哪些上下文」 |
| 触发式记忆 | 任务关闭/返工/裁决/人类拍板触发抽取的**候选** | 运行时 | 待审队列；批准/拒绝/合并 |
| 档案记忆 | 八类实体（人/员工/部门/项目/任务/决策/争议/能力） | 主管/助理审核晋升 | 来源、置信度、生效/失效、版本、编辑/删除 |
| 管理手册 | Agent 的分章判断规则，常驻 system 末尾 | 主管/助理提议 + 人类批准高风险修改 | diff、回滚、禁用 |

规则：**日志全量、档案精选、提示词极简**；写入必须可复用、可验证、决策相关、归属明确；删除留墓碑，删除后不再注入；投毒内容不得晋升为系统指令。

## 7. 权限与可见性

- 可见性：private / department / project / org / human-only。
- Agent 默认只看到与本部门/任务相关的消息与档案；跨部门通过结构化决策包/评审引用，不共享完整群聊。
- 人类可查看所有群聊，但读取 Agent 私有内容应进入「审计模式」并留痕。
- 作者 ≠ 评审者；审批人 ≠ 作者；Agent 不能改自己的角色卡/权限/预算，不能删除审计。

## 8. 消息、事件与轨迹

- **消息**：人可见的沟通与卡片，全部落库、默认进检索。
- **事件**：任务/评审/决策/审批/写事件等状态变化，驱动 UI 与 Agent。
- **轨迹**：模型 token 流、工具调用细节、调试日志；作为审计事件保留，**默认不进检索**。

「所有消息都存」不等于「所有模型思考都能被搜到」。

## 9. 本地优先与数据

- 默认只绑 127.0.0.1；数据在本地目录；DeepSeek 是唯一默认外联。
- 消息先落库再推送；断线用 seq/Last-Event-ID 补齐；Agent 用游标 + 幂等键。
- 索引可重建；删除同步到索引；备份/导出不锁定格式。
- 不做全库加密（v0.0.1 明确取舍）；数据目录权限 0700，不要放网络/同步盘。
